# Хосты и составные шаблоны — заметки к выпуску

Ветка: `codex/host-generation-redesign`. Миграция `e5c14a9d72b0` следует напрямую
за `f6a82c1d5e90` из `master`.

- Хост описывает одно подключение. Составные конфигурации настраиваются в шаблонах
  через директивы `marzban` и нативные секции Xray, Clash и sing-box.
- Старые параметры хостов переносятся сразу в `overrides`, а балансировщики —
  в шаблоны. Временные связи, поля балансировки и переименования формата исключены.
- Для YAML остаётся только `clash`. Каталог, ID шаблонов, отметки default,
  привязки, группы и исходный Jinja-текст сохраняются.
- Форматы API и URL: `v2ray`, `v2ray-json`, `clash`, `sing-box`, `outline`.
  Алиасы `json`, `xray-json`, `singbox`, `clash-meta`, `mihomo` отклоняются с HTTP 422.
  В существующих ссылках замените `/json` и `/xray-json` на `/v2ray-json`,
  `/singbox` — на `/sing-box`.
- Все дополнительные параметры XHTTP объединены в `transport.xhttp.extra`.
- Новый API `/api/hosts` заменяет прежние bulk/v2-методы и отдельный API балансировщиков.
- Форма содержит общие поля и динамически добавляемые параметры; шаблоны выбираются
  чипсами в общем комбобоксе. Для URI и Xray JSON доступны все шаблоны формата,
  для sing-box, Clash и Outline — только текущий default. Удаление чипа выключает
  формат; необязательный `template_id` в ссылке позволяет выбрать другой общий шаблон.
  Смена default применяется к существующим общим подпискам. Сохранённые привязки
  общих форматов не удаляются, но их ID больше не выбирают шаблон.
  ALPN использует мультиселект.
- «Скрыть из списка» исключает отдельное подключение из всех форматов подписок,
  включая URI/Base64 и Outline. Скрытые хосты доступны для составных шаблонов.
  Ранее сохранённый `is_hidden=true` теперь также скрывает URI и Outline.

Это изменение контракта для интеграций. Перед обновлением нужны резервная копия
и read-only preflight. Миграция проверяет данные и шаблоны до изменения схемы,
сохраняет исходные данные в архиве и поддерживает точный откат к `master`, пока
мигрированные настройки не редактировались. Порядок действий и ограничения для
БД с уже применёнными промежуточными ревизиями: [документация хостов](hosts.md#миграция-композиции).

Проверки миграции охватывают прямой upgrade, downgrade и повторное обновление
на временных SQLite-базах с внешними ключами и без них, сохранение исходных данных,
генерацию пяти форматов и отказ до DDL при конфликтах. Для MySQL/MariaDB проверяется
компиляция DDL; серверные миграции требуют отдельного стенда. Клиентские документы
не проверялись бинарниками Xray, Mihomo и sing-box. Рабочая БД не изменялась.
