# Единая модель хостов — заметки к выпуску

Ветка: `codex/host-generation-redesign`. Миграция: `a319d48e7062`.

- Обычные и составные подключения используют одну модель хоста и один pipeline генерации.
- Связи учитывают только прямых участников. Отдельная видимость настраивается для каждого хоста.
- Дополнительные параметры XHTTP объединены в `overrides.transport.xhttp.extra`.
- Создание начинается с общих полей; дополнительные поля добавляются через селект.
- Настройки балансировщика перенесены в форму хоста, включая параметры отдельных клиентов.
- Новый API `/api/hosts` заменяет прежние bulk/v2-методы и отдельный API балансировщиков.

Для внешних интеграций это изменение контракта. Перед обновлением нужны полная
резервная копия и preflight старой БД. После перехода на новые возможности откат
выполняется восстановлением копии; downgrade блокирует непредставимые старой схемой данные.
Порядок выпуска описан в [контракте хостов](hosts.md#перенос-и-выпуск).

Проверено: 78 Python-тестов, production-сборка dashboard, один Alembic head,
SQLite upgrade/downgrade/re-upgrade, создание и редактирование в браузере,
добавление связей и клиентских настроек, мобильная ширина 390 px.
Новые сообщения формы добавлены в en/ru/fa/zh. `git diff --check` проходит.

Ограничения проверки: MySQL/MariaDB — только компиляция DDL; клиентские документы
не запускались бинарниками Xray, Mihomo и sing-box. Эти проверки нужны на стенде
выпуска с используемыми в эксплуатации версиями клиентов. Рабочая БД не изменялась.
