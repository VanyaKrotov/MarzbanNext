# Шаблоны подписок MarzbanNext

Этот документ описывает реализацию MarzbanNext. Документы в `docs/subscriptions/`
описывают исходную реализацию Remnawave и не заменяют этот контракт.

## Форматы и хранение

В `subscription_templates` хранятся только полные клиентские конфигурации:

| Поле | Назначение |
| --- | --- |
| `id` | Числовой первичный ключ |
| `name` | Название, до 128 символов; уникально внутри формата |
| `format` | `v2ray`, `v2ray-json`, `clash-meta`, `sing-box`, `outline` |
| `content` | Исходный текст без переформатирования; TEXT, LONGTEXT в MySQL/MariaDB |
| `default_marker` | `1` у текущего шаблона по умолчанию, `NULL` у остальных |
| `created_at`, `updated_at` | Время создания и изменения в UTC |

Ограничение `UNIQUE(format, default_marker)` обеспечивает не более одного шаблона
по умолчанию на формат и допускает несколько пользовательских шаблонов.
API возвращает вычисляемое поле `is_default`, а не `default_marker`.
Сервис не разрешает удалить текущий шаблон по умолчанию или изменить его формат.
Переименование разрешено: привязки хостов используют ID, а статус default хранится отдельно от названия.
Повторяющиеся названия внутри формата отклоняются.

`clash-meta` — единый формат шаблонов и генерации для Clash Meta (Mihomo).
`clash` и `mihomo` остаются алиасами URL подписки и выбора семейства; отдельного
Mihomo target или второй карты настроек балансировщика нет.
`singbox` — псевдоним `sing-box`; `json` и `xray-json` — `v2ray-json`.
Base64 — кодирование результата `v2ray`, а не отдельный формат шаблона.

Параметры генераторов хранятся отдельными полями `runtime_settings`:
`clash_settings`, `singbox_settings`, `v2ray_settings`, `mux`, `user_agent`,
`grpc_user_agent`. Они редактируются в настройках, в разделе «Настройки генераторов».
Полные шаблоны доступны на отдельной странице «Шаблоны подписок».

## Привязки хоста

Таблица `host_subscription_templates`:

- первичный ключ `(host_id, format)` — один выбранный шаблон на формат у хоста;
- `host_id` ссылается на `hosts.id`, удаление хоста удаляет его привязки;
- `template_id` ссылается на `subscription_templates.id`, удаление используемого
  шаблона запрещено;
- формат привязки проверяется сервисом по формату выбранного шаблона;
- отсутствие строки означает, что формат выключен для хоста.

В API хоста привязки представлены как `subscription_template_ids`:

```json
{
  "v2ray": 4,
  "v2ray-json": 3,
  "sing-box": 2
}
```

В этом примере Clash и Outline выключены. Значения должны быть положительными
целыми ID; `null`, строки, булевы значения и неизвестные форматы запрещены.

| Операция | Поле отсутствует | Передан объект | Передан `{}` |
| --- | --- | --- | --- |
| Создание хоста | Привязать текущие defaults всех форматов | Использовать только переданные привязки | Выключить все форматы |
| Обновление хоста | Сохранить привязки | Полностью заменить привязки | Выключить все форматы |

Копирование хоста передаёт его точную карту привязок, включая выключенные форматы.
Автоматически создаваемые хосты новых инбаундов также получают все defaults.
Изменение default влияет только на последующее создание хостов. Изменение содержимого
шаблона сразу используется всеми уже привязанными хостами при следующей генерации.
Чтение хостов и генерация подписок не восстанавливают отсутствующие привязки.

Хосты редактируются по ID через `/api/hosts`; PATCH сохраняет пропущенные поля.
Старый массовый API и `/hosts/v2` удалены. Контракт описан в [документации хостов](hosts.md).

## Административный API

Все методы требуют sudo-администратора. Префикс: `/api/subscription-templates`.

| Метод | Путь | Данные / результат |
| --- | --- | --- |
| GET | `/` | `items`, `total`; фильтры `format`, `search`, `offset`, `limit` |
| POST | `/` | Создать: `name`, `format`, `content`; ответ 201 |
| GET | `/{id}` | Метаданные и исходный `content` |
| PATCH | `/{id}` | Изменить переданные поля `name`, `format`, `content` |
| DELETE | `/{id}` | Удалить свободный шаблон; ответ 204 |
| POST | `/{id}/clone` | Создать копию с переданным `name`; ответ 201 |
| POST | `/{id}/set-default` | Назначить default для формата, вернуть шаблон |

Фактический путь списка и создания — префикс без завершающего `/`.
`limit` по умолчанию 50, максимум 1000. Список содержит метаданные без `content`.
Изменить формат привязанного шаблона нельзя. Назначение default и снятие предыдущего
default выполняются в одной транзакции. Тексты конфигураций не кэшируются между запросами.

Ошибки: 401/403 — доступ; 404 — неизвестный ID; 409 — повтор названия, удаление
используемого/default-шаблона или недопустимая смена формата; 422 — некорректные
данные, Jinja2 или структура результирующего документа.

## Редактирование и рендеринг

Содержимое сохраняется как текст. Разрешены Jinja2, существующие фильтры `yaml`,
`except`, `only`, `datetime`, `bytesformat`, стандартные фильтры Jinja2 и функция `now()`.
Рендеринг полных шаблонов использует sandbox и строгую проверку отсутствующих переменных.
Проверка при сохранении выполняется на примерных данных, а не на реальных учётных данных клиента.
Это проверка шаблона и структуры, а не проверка конфигурации бинарниками всех клиентских ядер.

| Формат | Контекст шаблона | Применение |
| --- | --- | --- |
| `v2ray` | `links`, `host` | Для каждого хоста: сначала URI, затем шаблон; результаты объединяются строками, затем при необходимости кодируются в Base64 |
| `v2ray-json` | `host`, `remarks` | Полный JSON-профиль для каждого хоста; сгенерированные outbounds добавляются перед outbounds шаблона |
| `clash-meta` | `conf`, `proxy_remarks` | Полный YAML для общей подписки; `conf` содержит сгенерированные proxies и группы балансировщиков |
| `sing-box` | Функция `now()` без дополнительных переменных | Полный JSON-каркас; генератор добавляет outbounds и заполняет существующие selector/urltest с `outbounds: null` |
| `outline` | `config` | Обёртка существующего Outline-объекта; сохраняется прежнее поведение генератора одного SS-подключения |

Контекст `host` содержит `id`, `host_id`, `remark`, `address`, `port`, `inbound`,
`settings`. В JSON-шаблонах строки с переменными следует вставлять через `tojson`:

```jinja2
{
  "log": {"loglevel": "warning"},
  "outbounds": [],
  "description": {{ host.remark | tojson }}
}
```

Пустой `outbounds` подходит как минимальная основа Xray JSON, но клиентские inbounds,
DNS и маршрутизацию администратор задаёт в полном шаблоне по требованиям приложения.
Для Clash требуется массив `proxies`; для Xray JSON и sing-box — массив объектов
`outbounds`. URI-шаблон должен выдавать клиентские ссылки по одной на строку.

Шаблоны по умолчанию для URI и Outline сохраняют прежний результат:

```jinja2
{{ links | join('\n') }}
```

```jinja2
{{ config | tojson }}
```

## Выбор шаблона при запросе подписки

Сначала применяются доступные пользователю инбаунды, фильтры групп, выключенные хосты,
привязки форматов и существующие ограничения балансировщиков. Хост с выключенным
форматом исключается до рендеринга; другое семейство шаблонов вместо него не используется.
Если подходящих хостов нет, HTTP-ответ — **204 с пустым телом**.
Это правило действует и для автоматического определения приложения по User-Agent:
например, запрос JSON от v2rayN не превращается в URI, если JSON выключен.

У URI и обычных Xray JSON-профилей каждый хост использует собственный шаблон.
Автоматический Xray JSON-профиль использует шаблон хоста-владельца. Привязки остальных
участников разрешают формат; их полные шаблоны не вкладываются в профиль владельца.
Для агрегированных Clash, sing-box и Outline требуется один ID шаблона среди
попавших в результат хостов. Несколько разных ID возвращают **409**.
При проверке учитываются шаблоны выдаваемых обычных и автоматических профилей;
шаблон участника, используемого только как зависимость, не создаёт конфликт.

Для явного выбора общего шаблона поддерживается положительный query-параметр
`template_id` как на автоматическом URL, так и на URL с явным форматом:

```text
/sub/<token>/clash-meta?template_id=12
/sub/<token>/sing-box?groups=eu&template_id=15
```

Префикс `/sub` здесь пример; используется настроенный `XRAY_SUBSCRIPTION_PATH`.
Параметр выбирает шаблон только требуемого формата; неправильный или неизвестный
ID даёт 422 при наличии подходящих хостов. Выключенные у хоста форматы он не включает.
Можно также запросить группу хостов с одинаковым выбранным шаблоном без `template_id`.

## Миграция и выпуск

Ревизия `f6a82c1d5e90`, предыдущая `e2f7a3c9b4d1`:

1. Переносит три полных существующих шаблона в `default` соответствующих форматов,
   сохраняя исходный текст и `updated_at`.
2. Переносит шесть вспомогательных конфигураций в поля `runtime_settings` без изменения текста.
3. Создаёт identity-шаблоны `default` для URI и Outline.
4. Один раз привязывает все существующие хосты ко всем пяти defaults.

Старый административный endpoint `/api/settings/subscription-templates` удалён.
Обновляйте сервер и dashboard вместе. После резервного копирования примените миграции
и соберите интерфейс обычным способом проекта:

```bash
alembic upgrade head
cd app/dashboard
VITE_BASE_API=/api npm run build -- --outDir build --assetsDir statics
```

Если API доступен по другому базовому пути, передайте его вместо `/api`.
В разработке проверки миграции выполняются только на временных базах; сами изменения
кода не мигрируют рабочую БД.

Downgrade возвращает девять записей старой схемы: три текущих default-шаблона и шесть
вспомогательных конфигураций. Пользовательские шаблоны и индивидуальные привязки хостов
старая схема представить не может — они теряются при downgrade. Для их сохранения
перед откатом нужен полный backup.

## Проверки

`tests/test_subscription_templates.py` проверяет административный API, валидацию,
привязки хостов, все пять генераторов, live-обновление содержимого, aliases, Base64,
балансировщики, конфликты общих шаблонов и отсутствие fallback при определении клиента.
`tests/test_subscription_template_migration.py` проверяет свежую установку, перенос
пользовательского текста, downgrade и повторный upgrade на SQLite.
Для MySQL/MariaDB дополнительно проверяется компиляция DDL; интеграционная миграция
на работающем MySQL-сервере не выполнялась.
