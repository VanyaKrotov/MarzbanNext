# Шаблоны подписок MarzbanNext

Этот документ описывает реализацию MarzbanNext. Документы в `docs/subscriptions/`
описывают исходную реализацию Remnawave и не заменяют этот контракт.

## Форматы и хранение

В `subscription_templates` хранятся только полные клиентские конфигурации:

| Поле | Назначение |
| --- | --- |
| `id` | Числовой первичный ключ |
| `name` | Название, до 128 символов; уникально внутри формата |
| `format` | `v2ray`, `v2ray-json`, `clash`, `sing-box`, `outline` |
| `content` | Исходный текст без переформатирования; TEXT, LONGTEXT в MySQL/MariaDB |
| `default_marker` | `1` у текущего шаблона по умолчанию, `NULL` у остальных |
| `created_at`, `updated_at` | Время создания и изменения в UTC |

Ограничение `UNIQUE(format, default_marker)` обеспечивает не более одного шаблона
по умолчанию на формат и допускает несколько пользовательских шаблонов.
API возвращает вычисляемое поле `is_default`, а не `default_marker`.
Сервис не разрешает удалить текущий шаблон по умолчанию или изменить его формат.
Переименование разрешено: привязки хостов используют ID, а статус default хранится отдельно от названия.
Повторяющиеся названия внутри формата отклоняются.

`clash` — единый формат шаблонов и генерации для Clash Meta (Mihomo).
`clash-meta` и `mihomo` не принимаются как имена формата или URL подписки; отдельного
Mihomo target нет.
`singbox` — псевдоним `sing-box`; `json` и `xray-json` — `v2ray-json`.
Base64 — кодирование результата `v2ray`, а не отдельный формат шаблона.

Параметры генераторов хранятся отдельными полями `runtime_settings`:
`clash_settings`, `singbox_settings`, `v2ray_settings`, `mux`, `user_agent`,
`grpc_user_agent`. Они редактируются в настройках, в разделе «Настройки генераторов».
Полные шаблоны доступны на отдельной странице «Шаблоны подписок».

## Привязки хоста

Таблица `host_subscription_templates`:

- первичный ключ `(host_id, format)` — один выбранный шаблон на формат у хоста;
- `host_id` ссылается на `hosts.id`, удаление хоста удаляет его привязки;
- `template_id` ссылается на `subscription_templates.id`, удаление используемого
  шаблона запрещено;
- формат привязки проверяется сервисом по формату выбранного шаблона;
- отсутствие строки означает, что формат выключен для хоста.

В API хоста привязки представлены как `subscription_template_ids`:

```json
{
  "v2ray": 4,
  "v2ray-json": 3,
  "sing-box": 2
}
```

В этом примере Clash и Outline выключены. Значения должны быть положительными
целыми ID; `null`, строки, булевы значения и неизвестные форматы запрещены.

| Операция | Поле отсутствует | Передан объект | Передан `{}` |
| --- | --- | --- | --- |
| Создание хоста | Привязать текущие defaults всех форматов | Использовать только переданные привязки | Выключить все форматы |
| Обновление хоста | Сохранить привязки | Полностью заменить привязки | Выключить все форматы |

Копирование хоста передаёт его точную карту привязок, включая выключенные форматы.
Автоматически создаваемые хосты новых инбаундов также получают все defaults.
Изменение default влияет только на последующее создание хостов. Изменение содержимого
шаблона сразу используется всеми уже привязанными хостами при следующей генерации.
Чтение хостов и генерация подписок не восстанавливают отсутствующие привязки.

Хосты редактируются по ID через `/api/hosts`; PATCH сохраняет пропущенные поля.
Старый массовый API и `/hosts/v2` удалены. Контракт описан в [документации хостов](hosts.md).

## Административный API

Все методы требуют sudo-администратора. Префикс: `/api/subscription-templates`.

| Метод | Путь | Данные / результат |
| --- | --- | --- |
| GET | `/` | `items`, `total`; фильтры `format`, `search`, `offset`, `limit` |
| POST | `/` | Создать: `name`, `format`, `content`; ответ 201 |
| GET | `/{id}` | Метаданные и исходный `content` |
| PATCH | `/{id}` | Изменить переданные поля `name`, `format`, `content` |
| DELETE | `/{id}` | Удалить свободный шаблон; ответ 204 |
| POST | `/{id}/clone` | Создать копию с переданным `name`; ответ 201 |
| POST | `/{id}/set-default` | Назначить default для формата, вернуть шаблон |

Фактический путь списка и создания — префикс без завершающего `/`.
`limit` по умолчанию 50, максимум 1000. Список содержит метаданные без `content`.
Изменить формат привязанного шаблона нельзя. Назначение default и снятие предыдущего
default выполняются в одной транзакции. Тексты конфигураций не кэшируются между запросами.

Ошибки: 401/403 — доступ; 404 — неизвестный ID; 409 — повтор названия, удаление
используемого/default-шаблона или недопустимая смена формата; 422 — некорректные
данные, Jinja2 или структура результирующего документа.

## Редактирование и рендеринг

Содержимое сохраняется как текст. Разрешены Jinja2, существующие фильтры `yaml`,
`except`, `only`, `datetime`, `bytesformat`, стандартные фильтры Jinja2 и функция `now()`.
Рендеринг полных шаблонов использует sandbox и строгую проверку отсутствующих переменных.
Проверка при сохранении выполняется на примерных данных, а не на реальных учётных данных клиента.
Это проверка шаблона и структуры, а не проверка конфигурации бинарниками всех клиентских ядер.

| Формат | Контекст шаблона | Применение |
| --- | --- | --- |
| `v2ray` | `links`, `host` | Для каждого хоста: сначала URI, затем шаблон; результаты объединяются строками, затем при необходимости кодируются в Base64 |
| `v2ray-json` | `host`, `remarks`, `host_ids` | Полный JSON-профиль для каждого хоста; сгенерированные outbounds добавляются перед outbounds шаблона |
| `clash` | `conf`, `proxy_remarks`, `host_ids` | Полный YAML для общей подписки; `conf` содержит видимые сгенерированные proxies |
| `sing-box` | `host_ids`, функция `now()` | Полный JSON-каркас; генератор добавляет outbounds и заполняет существующие selector/urltest с `outbounds: null` |
| `outline` | `config` | Обёртка существующего Outline-объекта; сохраняется прежнее поведение генератора одного SS-подключения |

`host_ids` в шаблонах JSON/YAML содержит ID всех разрешённых источников этого формата,
включая скрытые, до применения фильтра получателей. Это позволяет условно включать
секции Jinja без обхода прав доступа.

Контекст `host` содержит `id`, `host_id`, `remark`, `address`, `port`, `inbound`,
`settings`. В JSON-шаблонах строки с переменными следует вставлять через `tojson`:

```jinja2
{
  "log": {"loglevel": "warning"},
  "outbounds": [],
  "description": {{ host.remark | tojson }}
}
```

Пустой `outbounds` подходит как минимальная основа Xray JSON, но клиентские inbounds,
DNS и маршрутизацию администратор задаёт в полном шаблоне по требованиям приложения.
Для Clash требуется массив `proxies`; для Xray JSON и sing-box — массив объектов
`outbounds`. URI-шаблон должен выдавать клиентские ссылки по одной на строку.

Шаблоны по умолчанию для URI и Outline сохраняют прежний результат:

```jinja2
{{ links | join('\n') }}
```

```jinja2
{{ config | tojson }}
```

## Выбор шаблона при запросе подписки

Сначала применяются доступные пользователю инбаунды, фильтры групп, выключенные хосты,
привязки форматов и совместимость подключений. Хост с выключенным
форматом исключается до рендеринга; другое семейство шаблонов вместо него не используется.
Если подходящих хостов нет, HTTP-ответ — **204 с пустым телом**.
Это правило действует и для автоматического определения приложения по User-Agent:
например, запрос JSON от v2rayN не превращается в URI, если JSON выключен.

У URI и обычных Xray JSON-профилей каждый хост использует собственный шаблон.
Автоматический Xray JSON-профиль использует шаблон хоста-владельца. Привязки остальных
участников разрешают формат; их полные шаблоны не вкладываются в профиль владельца.
Для агрегированных Clash, sing-box и Outline требуется один ID шаблона среди
попавших в результат хостов. Несколько разных ID возвращают **409**.
При проверке учитываются шаблоны выдаваемых обычных и автоматических профилей;
шаблон участника, используемого только как зависимость, не создаёт конфликт.

Для явного выбора общего шаблона поддерживается положительный query-параметр
`template_id` как на автоматическом URL, так и на URL с явным форматом:

```text
/sub/<token>/clash?template_id=12
/sub/<token>/sing-box?groups=eu&template_id=15
```

Префикс `/sub` здесь пример; используется настроенный `XRAY_SUBSCRIPTION_PATH`.
Параметр выбирает шаблон только требуемого формата; неправильный или неизвестный
ID даёт 422 при наличии подходящих хостов. Выключенные у хоста форматы он не включает.
Можно также запросить группу хостов с одинаковым выбранным шаблоном без `template_id`.

## Композиция в шаблонах

Объект `marzban` выбирает хосты и добавляет их подключения в клиентскую конфигурацию.
Используется только это пространство имён. Перед выдачей подписки служебные ключи удаляются.
Стратегии, интервалы, URL проверки, маршрутизация и допуски — нативные поля клиента.
Проверку задержки и переключение выполняет клиентское ядро, а не панель.
В примерах «лучшее подключение» означает меньшую задержку до проверочного URL;
это не измерение максимальной скорости скачивания.

### Общие параметры выбора источников

| Параметр | Значение и поведение |
| --- | --- |
| `selector` | Необязательный объект выбора по ID хостов или группам. Его результат дополнительно ограничивается `selectFrom` |
| `selector.type: "ids"` | `values` содержит положительные целые ID хостов, например `[11, 12, 13]`. Строки и булевы значения запрещены. Порядок сохраняется, повторы удаляются |
| `selector.type: "groups"` | `values` содержит непустые строковые ID групп, например `["eu", "backup"]`, а не отображаемые названия. Достаточно участия хотя бы в одной группе; порядок хостов — `position,id` |
| `selector.type: "sameGroupsAsRecipient"` | Только Xray: выбрать хосты с пересечением групп хоста-получателя. `values` следует пропустить |
| `selectFrom: "ALL"` | Разрешить и скрытые, и видимые источники |
| `selectFrom: "HIDDEN"` | Разрешить только хосты с включённым флагом «Скрыть из списка» |
| `selectFrom: "VISIBLE"` | Разрешить только хосты с выключенным флагом «Скрыть из списка» |

Без `selector` выбираются все доступные источники в пределах `selectFrom`.
Для `VISIBLE` без `selector` используется видимый список текущего ответа,
учитывающий фильтр групп и хостов-получателей. Явные ID или группы могут выбрать
другие разрешённые пользователю источники вне этого фильтра.
По умолчанию `selectFrom` равен `HIDDEN` для Xray `injectHosts` и `VISIBLE`
для Clash и sing-box. Поэтому даже явно перечисленные ID скрытых хостов
не попадут в группу Clash или sing-box без `selectFrom: "ALL"` либо `"HIDDEN"`.

Выбор выполняется после проверки включения хоста, разрешённых инбаундов пользователя,
доступности формата и поддержки транспорта. `ALL` не обходит эти ограничения:
неизвестные, отключённые и недоступные источники пропускаются.
Для каждого выбранного хоста используются его собственные инбаунд, адрес, порт,
переопределения и учётные данные протокола. Шаблоны источников не раскрываются:
вложенные составные конфигурации не создаются. Привязка источника к шаблону
нужного формата обязательна, но это может быть другой шаблон.
Скрытые источники с другими привязками не создают конфликт общих шаблонов.

Во всех примерах ниже источники имеют ID **11, 12 и 13**. Замените их своими ID.
Чтобы выбирать по группам, замените объект `selector` в соответствующей директиве:

```json
{
  "type": "groups",
  "values": ["eu", "backup"]
}
```

Примеры содержат локальный прокси на `127.0.0.1:10808`; это порт клиентского
приложения, а не порт инбаунда сервера. Подстройте локальные inbounds, DNS
и маршрутизацию под приложение, в которое будет импортирована подписка.

### Xray JSON

Формат шаблона — `v2ray-json`. Объект `marzban` находится в корне документа.
Для каждого видимого хоста-получателя рендерится отдельный профиль.
В этом примере назначьте шаблон отдельному видимому хосту с ID **10**;
он служит получателем профиля, а **11–13** — источниками пула.
Получатель остаётся обычным хостом с действующим инбаундом и включённым форматом.

| Параметр `marzban` | По умолчанию | Назначение |
| --- | --- | --- |
| `addVirtualHostAsOutbound` | `true` | Добавить собственное подключение получателя с тегом `proxy`. При `false` оно не добавляется |
| `injectHosts` | `[]` | Список выборок источников. Каждая содержит общие параметры `selector`, `selectFrom` и обязательный `tagPrefix` |
| `injectHosts[].tagPrefix` | Обязателен | Непустой префикс длиной до 256 символов. Первый источник получает этот тег, следующие — суффиксы `-2`, `-3` и далее |

```json
{
  "log": {
    "loglevel": "warning"
  },
  "inbounds": [
    {
      "tag": "socks",
      "listen": "127.0.0.1",
      "port": 10808,
      "protocol": "socks",
      "settings": {
        "auth": "noauth",
        "udp": true
      }
    }
  ],
  "outbounds": [],
  "marzban": {
    "addVirtualHostAsOutbound": false,
    "injectHosts": [
      {
        "selector": {
          "type": "ids",
          "values": [11, 12, 13]
        },
        "selectFrom": "ALL",
        "tagPrefix": "pool"
      }
    ]
  },
  "observatory": {
    "subjectSelector": ["pool"],
    "probeUrl": "https://www.gstatic.com/generate_204",
    "probeInterval": "300s",
    "enableConcurrency": true
  },
  "routing": {
    "balancers": [
      {
        "tag": "best",
        "selector": ["pool"],
        "strategy": {
          "type": "leastPing"
        }
      }
    ],
    "rules": [
      {
        "type": "field",
        "network": "tcp,udp",
        "balancerTag": "best"
      }
    ]
  }
}
```

Панель создаст аутбаунды `pool`, `pool-2`, `pool-3`. `subjectSelector` наблюдателя
и `selector` балансировщика сопоставляются с префиксами тегов, поэтому `pool`
охватывает все три подключения. `enableConcurrency: true` включает параллельную
проверку; после завершения проверок выдерживается `probeInterval: "300s"`.
Стратегия `leastPing` выбирает подключение по результатам наблюдения,
а правило с `balancerTag: "best"` направляет TCP/UDP-трафик через балансировщик.
Нативные поля описаны в документации Xray: [наблюдение](https://xtls.github.io/config/observatory.html)
и [маршрутизация](https://xtls.github.io/config/routing.html).

Особенности выбора Xray:

- Получатель всегда исключается из `injectHosts`, даже если его ID указан явно.
  Чтобы включить собственное подключение, используйте `addVirtualHostAsOutbound: true`.
  Тогда оно получит тег `proxy`; для участия в приведённом балансировщике добавьте
  `proxy` и в `observatory.subjectSelector`, и в `routing.balancers[].selector`.
- Без `selector` выборка охватывает все разрешённые скрытые источники по умолчанию.
  Для групп самого получателя используйте `selector: {"type": "sameGroupsAsRecipient"}`.
- Каждая выборка `injectHosts` должна дать хотя бы один источник, иначе профиль пропускается,
  даже если собственное подключение включено. Коллизии тегов отклоняются;
  для нескольких выборок задавайте разные префиксы без пересечения с другими тегами.
  Фрагментация использует отдельные dialer-теги вне префикса пула.

Панель сохраняет нативные `leastPing`, `leastLoad`, `random`, `roundRobin` и их поля
без автоматической замены стратегии. Используйте поддерживаемую вашим ядром схему.

### Clash

Формат шаблона — `clash`. Объект `marzban` размещается в `proxy-groups[]`
или у `proxy-providers.<name>` с `type: "inline"`. Генерируется общая конфигурация,
а не отдельный профиль для каждого видимого хоста.
Пример записан в JSON; та же схема с подсказками и описаниями применяется к YAML.
Jinja также поддерживается.
Итоговая подписка выдаётся в YAML.

| Параметр `marzban` | По умолчанию | Назначение |
| --- | --- | --- |
| `include-proxies` | `true` | В группе добавить имена выбранных подключений после явного `proxies`, удаляя повторы. В inline-провайдере заменить `payload` выбранными подключениями. При `false` сохранить явный список |
| `selector`, `selectFrom` | Без селектора, `VISIBLE` | Общие параметры выбора источников. `sameGroupsAsRecipient` не поддерживается |

```json
{
  "mixed-port": 10808,
  "allow-lan": false,
  "mode": "rule",
  "log-level": "warning",
  "proxies": [],
  "proxy-groups": [
    {
      "name": "Best",
      "type": "url-test",
      "proxies": [],
      "url": "https://www.gstatic.com/generate_204",
      "interval": 300,
      "tolerance": 50,
      "lazy": false,
      "marzban": {
        "include-proxies": true,
        "selectFrom": "ALL",
        "selector": {
          "type": "ids",
          "values": [11, 12, 13]
        }
      }
    }
  ],
  "rules": [
    "MATCH,Best"
  ]
}
```

Панель добавит подключения 11–13 в корневой `proxies`, а их имена — в `Best.proxies`.
Группа `url-test` проверяет задержку с интервалом `300` секунд.
`tolerance: 50` задаёт допуск переключения в миллисекундах;
`lazy: false` отключает пропуск проверок из-за отсутствия использования группы.
Правило `MATCH,Best` направляет трафик через автоматический выбор.
Нативные поля описаны в [документации URL-Test](https://wiki.metacubex.one/en/config/proxy-groups/url-test/)
и [общих параметров групп](https://wiki.metacubex.one/en/config/proxy-groups/).

Особенности выбора Clash:

- Хост, по привязке которого выбран общий шаблон, не исключается из источников.
  В примере участвуют все доступные хосты из `[11, 12, 13]`.
- Группа без `marzban` получает стандартные видимые подключения текущего ответа.
  Чтобы сохранить только явно заданные `proxies`, укажите
  `"marzban": {"include-proxies": false}`. Например, это нужно для ручной группы
  с единственным элементом `"Best"`. Имя поля — именно `include-proxies`.
- Корневой `proxies` содержит статические, видимые и используемые группами скрытые
  подключения. Поэтому селектор ограничивает конкретную группу, но не удаляет
  остальные видимые подключения из общей конфигурации.
- Скрытые источники, использованные только inline-провайдером, остаются в его `payload`
  и не добавляются в корневой список. Неиспользуемые скрытые узлы отсутствуют.
  Jinja `conf.proxies` не дублирует подключения.
- Если группа с включённой директивой осталась без `proxies` и без `use`,
  либо включённый inline-провайдер получил пустой `payload`, конфигурация пропускается.

### sing-box

Формат шаблона — `sing-box`. Объект `marzban` разрешён в `outbounds[]`
только у типов `urltest` и `selector`. Генерируется одна общая конфигурация.

| Параметр `marzban` | По умолчанию | Назначение |
| --- | --- | --- |
| `includeProxies` | `true` | Заменить список `outbounds` группы выбранными тегами, удаляя повторы. При `false` сохранить явный список |
| `selector`, `selectFrom` | Без селектора, `VISIBLE` | Общие параметры выбора источников. `sameGroupsAsRecipient` не поддерживается |

```json
{
  "log": {
    "level": "warn"
  },
  "inbounds": [
    {
      "type": "mixed",
      "tag": "mixed-in",
      "listen": "127.0.0.1",
      "listen_port": 10808
    }
  ],
  "outbounds": [
    {
      "type": "urltest",
      "tag": "best",
      "outbounds": [],
      "url": "https://www.gstatic.com/generate_204",
      "interval": "300s",
      "tolerance": 50,
      "interrupt_exist_connections": false,
      "marzban": {
        "includeProxies": true,
        "selectFrom": "ALL",
        "selector": {
          "type": "ids",
          "values": [11, 12, 13]
        }
      }
    }
  ],
  "route": {
    "final": "best"
  }
}
```

Панель создаст аутбаунды хостов 11–13 и заполнит их тегами `best.outbounds`.
`urltest` проверяет задержку с интервалом `"300s"`; `tolerance: 50` задаёт допуск
в миллисекундах. `route.final: "best"` направляет трафик через автоматический выбор.
`interrupt_exist_connections: false` отключает принудительное прерывание существующих
входящих соединений при смене выбранного подключения.
Нативные поля описаны в [документации sing-box URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/).

Особенности выбора sing-box:

- Как и в Clash, нет исключения хоста-получателя. Явная выборка ограничивает
  состав `best.outbounds`; другие видимые подключения могут остаться в корневом
  `outbounds`, но через `route.final: "best"` они автоматически не выбираются.
- Имя поля — `includeProxies`. При `true` список группы заменяется выборкой,
  тогда как Clash дополняет явный список. При `false` список сохраняется.
- У группы типа `selector` директива без `selector` дополнительно включает
  существующие группы `urltest`. Она не включает саму группу, а также статические
  `direct` и `block`. При явном `marzban.selector` используются только выбранные
  подключения хостов. У `urltest` вложенные группы автоматически не добавляются.
- Без директив заполняется только `outbounds: null`; явные списки не переписываются.
  Пустой `outbounds: []` без включённой директивы не означает «добавить все хосты».
  Если включённая директива дала пустой список, конфигурация пропускается.
  Нативные значения `0` и `false` сохраняются без подмены значениями по умолчанию.

### Как подключить примеры к подписке

1. Создайте шаблон нужного формата и замените ID источников своими.
   У каждого источника должны быть включены хост и соответствующий формат,
   а пользователь должен иметь доступ к его инбаунду.
2. Для Xray назначьте шаблон видимому получателю, например хосту 10.
   Хосты 11–13 можно скрыть флагом «Скрыть из списка», чтобы они не создавали
   отдельных профилей. Назначение одного составного шаблона нескольким видимым
   получателям создаст несколько Xray-профилей.
3. Для Clash и sing-box назначьте общий шаблон видимым хостам соответствующего
   ответа либо укажите `template_id` явно. Разные шаблоны у видимых хостов
   общей подписки вызывают конфликт `409`, если общий шаблон не выбран явно.
4. Если все источники Clash или sing-box скрыты, запросите шаблон через `template_id`.
   Без явного шаблона и видимых получателей выдача будет пустой.

Например, если созданные шаблоны Clash и sing-box имеют ID 55 и 56:

```text
/sub/<token>/clash?template_id=55
/sub/<token>/sing-box?template_id=56
```

Замените `/sub` на настроенный `XRAY_SUBSCRIPTION_PATH`, `<token>` — токен подписки,
а числа — ID созданных шаблонов. `template_id` выбирает шаблон нужного формата,
но не включает выключенный у источника формат и не отменяет ограничения доступа.
Для Xray явный `template_id` не создаёт получателя из скрытого хоста:
видимый получатель всё равно необходим. Скрытие исключает отдельные подключения
из всех форматов подписок, включая URI/Base64 и Outline.

### Редактирование директив и ошибки

Источники задаются прямо в тексте конфигурации через `marzban`, без отдельных
полей и предпросмотра. В Xray объект находится в корне документа; в sing-box —
в outbound типа `selector`/`urltest`; в Clash — в proxy-group или inline proxy-provider.
JSON-редактор дополняет нативную схему формата определениями директив backend:
подсказывает параметры, их значения по умолчанию и ограничения. ID хостов должны
быть положительными целыми числами, ID групп — непустыми строками;
`sameGroupsAsRecipient` разрешён только для Xray и не принимает `values`.

Схемы разделены по форматам и содержат описания полей, ограничения типов и примеры:

- Xray JSON переиспользует подробную схему Xray-core: протоколы, транспорт, TLS/Reality,
  DNS, наблюдатели и маршрутизацию. Для клиентского профиля не требуются управляемые
  серверные теги. Дополнительно описаны `marzban` и настройки `leastLoad`.
- Clash использует одну схему для JSON и YAML: прокси, группы, inline-провайдеры,
  маршрутизацию и директивы `marzban`.
- sing-box описывает локальные слушатели, аутбаунды, группы выбора, параметры URLTest
  и `marzban`. Outline описывает поля сформированного Shadowsocks-объекта.
- URI — текстовый список ссылок, поэтому JSON Schema к нему не применяется.
  В нём доступны подсказки `links`, полей `host` и фильтров Jinja.

Подсказки Jinja доступны во всех форматах и соответствуют их контексту: например,
`config` в Outline, `conf` в Clash, `host_ids` в составных шаблонах.
Исходные блоки Jinja не проверяются как готовый JSON/YAML: сервер проверяет результат
после рендеринга при сохранении и генерации. Подсветка редактора не заменяет проверку
полученного документа клиентским ядром.

| Метод | Путь под `/api/subscription-templates` | Назначение |
| --- | --- | --- |
| GET | `/capabilities` | JSON Schema директив для редактора; только sudo |

Маршруты предпросмотра `/preview` и `/preview-users` удалены. Редактор не загружает
пользователей, хосты или группы. Выбор источников при выдаче подписки по-прежнему
учитывает отключение, привязку формата, разрешённые инбаунды и совместимость подключения.
Неизвестные и дублирующиеся теги, неверные ссылки и циклы отклоняются с 422.
Пустой обязательный пул пропускает неработоспособный документ; отсутствие результатов
в публичной подписке возвращает 204. Конфликт шаблонов общей подписки — 409.
Для Clash и sing-box явный `template_id` позволяет собрать общую конфигурацию
даже при всех скрытых источниках; без явного шаблона и видимых получателей выдача пустая.

## Миграция и выпуск

Актуальный перенос связей, настроек и архива отката описан в [документации хостов](hosts.md).
Миграция сохраняет первоначальный текст шаблона без добавленных Jinja-обёрток.
Параметры перенесённых балансировщиков хранятся отдельно в служебном JSON
`migration_settings` и применяются к документу после выполнения исходного Jinja.
Текстовые правки и клонирование шаблона сохраняют эти параметры; смена формата
неиспользуемого шаблона сбрасывает их. В новых шаблонах параметры `marzban`
задаются непосредственно в конфигурации. Клиент получает только итоговый JSON/YAML.
Конфликты, которые нельзя преобразовать без потери данных, прекращают обновление до DDL.
Миграции `master` остаются неизменными. Все изменения этой ветки объединены в одну ревизию:
`e5c14a9d72b0` следует непосредственно за `f6a82c1d5e90` и сразу переносит
старые балансировщики в настройки шаблонов, без временных связей хостов и переименований формата.
Обновление с промежуточных схем этой ветки не поддерживается.

Применяйте миграции и обновляйте backend/dashboard вместе. В разработке рабочая БД
не используется для проверки. Бинарники клиентских ядер не заменяются Python-проверками:
структурные тесты не подтверждают совместимость со всеми версиями клиентских приложений.
