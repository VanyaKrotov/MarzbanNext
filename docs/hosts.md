# Хосты и клиентские конфигурации

Хост описывает собственное подключение к одному инбаунду. Объединение подключений
настраивается в [шаблонах подписок](subscription-templates.md).

## Данные

| Поле `hosts` | Назначение |
| --- | --- |
| `id` | Стабильный числовой ID |
| `inbound_id` | Инбаунд подключения |
| `remark`, `address` | Примечание и адрес с существующими переменными, CSV и wildcard |
| `port` | Порт; SQL NULL наследует порт инбаунда |
| `enabled` | Разрешение выдавать подключение, в том числе через шаблоны |
| `position` | Общий порядок хостов |
| `is_hidden` | «Скрыть из списка»: исключить отдельное подключение из всех форматов подписок; default false |
| `overrides` | Проверяемые необязательные переопределения; default `{}` |
| `created_at`, `updated_at` | Время в UTC |

Группы и привязки шаблонов остаются отдельными отношениями. Таблицы `host_links`,
полей `show_when_composed` и `balancer_settings` больше нет.
API возвращает также `inbound_tag`, `inbound_port`, `groups`, `subscription_template_ids`.
Ключи `subscription_template_ids` — только `v2ray`, `v2ray-json`, `clash`, `sing-box`, `outline`.
Псевдонимы форматов не принимаются.
В таблице показывается `port ?? inbound_port`; наследуемый `port` остаётся `null`.
Хосты отображаются таблицей на всех размерах экрана. На мобильных устройствах
горизонтальная прокрутка открывает все колонки. ID хоста отображается отдельной
колонкой таблицы и справа от заголовка диалога редактирования. Он доступен для выбора источников в шаблонах
через `selector: {"type": "ids", "values": [11, 12]}`. При создании ID ещё не назначен.

В форме группы находятся под инбаундом, адрес и порт — в одной строке,
переключатель включения — справа от примечания. Кнопка «+» у «Дополнительно»
открывает меню безопасности, транспорта, соединения, подписки и видимости.
Добавленные параметры исключаются из меню; крестик удаляет поле и возвращает наследование.
Текстовые поля сохраняют значение инпута, включая пустую строку.
Boolean-параметры отображаются переключателями слева от названия. Добавленное поле
с выключенным переключателем задаёт `false`, включённый переключатель — `true`.
Чтобы вернуть значение по умолчанию, удалите поле крестиком. Сохранённые `true`/`false`
отображаются без изменения значения; селекта «По умолчанию» у boolean-параметров нет.
В текстовых полях есть примеры ввода. Для сложных форматов и JSON-параметров
справка открывается нажатием на иконку информации справа от названия.
В форме используются короткие названия «Host» и «Шаблоны».
Fingerprint (`security.fingerprint`) выбирается селектом из стандартных профилей
Xray. Сохранённый профиль вне списка отображается и сохраняется без замены.
«По умолчанию клиента» задаёт явный `fingerprint: ""`; удаление поля возвращает наследование.
ALPN выбирается мультиселектом `h3`, `h2`, `http/1.1` и сохранённых нестандартных значений.
Очистка выбора задаёт явный `[]`; удаление поля возвращает наследование.

«Параметры клиента» добавляются в группе «Подписка» и задаются единым JSON-объектом:

```json
{
  "clash": { "ip_version": "ipv6-prefer", "x25519": false },
  "server_description": "Europe"
}
```

`clash.ip_version` принимает `dual`, `ipv4`, `ipv6`, `ipv4-prefer`, `ipv6-prefer`.
`clash.x25519` включает или отключает поддержку X25519MLKEM768 в Clash Reality.
`server_description` задаёт описание сервера для клиентов с расширенной поддержкой;
пустая строка сохраняется, но не добавляет описание в подписку.
Формат `overrides.clients` в API не меняется.

Описание задаётся в «Дополнительно» → «Подписка» → «Параметры клиента» → «Настроить»:

```json
{ "server_description": "Европа" }
```

Отдельное поле описания не требуется. JSON-поле доступно для любого инбаунда;
при открытии хоста с сохранённым `overrides.clients` оно добавляется в форму автоматически.
В Monaco есть подсказка и пример для `server_description`.

При запросе подписки описание включается для User-Agent, начинающихся с
`FlClashX/`, `FlClash X/`, `Flowvy/`, `prizrak-box/`, `koala-clash/`, `Happ/`, `INCY/`.
Регистр учитывается. Список соответствует
[поддерживаемым расширенным клиентам Remnawave](https://github.com/remnawave/backend/blob/52321390ac4efe04a610811446d87335f1d10a93/src/modules/subscription-template/constants/extended-clients.ts).
У остальных клиентов, включая обычные Clash, FlClash и v2rayNG, автоматическое описание не выдаётся.

| Формат | Куда попадает описание |
| --- | --- |
| Xray JSON | `meta.serverDescription` всей конфигурации. Для составного профиля используется описание хоста-получателя. |
| Clash | `serverDescription` конкретного proxy, включая источники составного шаблона. |
| URI / Base64 | Суффикс `?serverDescription=<Base64 UTF-8>` после полной ссылки, включая её fragment. Base64-подписка кодируется после добавления суффикса. |
| sing-box / Outline | Автоматическое описание не добавляется. |

Текст хранится без Base64-кодирования и не меняется при выборе другого клиента.
При прямом вызове генератора без User-Agent описание не добавляется.
Явно заданные поля пользовательских шаблонов и операции Mapper выполняются по своим правилам.

Для JSON-полей (параметры клиента, XHTTP extra, MUX, SockOpt, Final mask,
Mapper) кнопка «Настроить» справа от названия открывает отдельный диалог
с Monaco Editor. Схема соответствующего объекта из `/api/hosts/capabilities`
используется для автодополнения и проверки значений. «Сохранить» применяет JSON
к форме, «Отмена» или закрытие диалога оставляет прежнее значение. Для отправки на сервер
нужно сохранить сам хост. Удаление поля возвращает наследование.
Шаблоны выбираются комбобоксом с чипсами `format:name`, по одному на формат.
Удаление чипа исключает формат. Флаг «Скрыть из списка» действует во всех форматах подписок.

### Названия и справка полей

В меню, заголовках JSON-редакторов и справке используются названия `SockOpt`, `MUX`, `Mapper`.
Подсказки формы кратко объясняют назначение и формат; подробные ограничения остаются в схемах Monaco.

| Параметр | Значение / формат | Назначение |
| --- | --- | --- |
| Адрес | IP-адрес или домен | Адрес подключения. Через запятую — случайный выбор; `*` — случайная строка. Доступны переменные. |
| SNI | Текст | Имя сервера TLS/REALITY. Через запятую — случайный выбор; `*` — случайная строка. Пустое значение задаёт пустой SNI. |
| Безопасность | TLS / Нет | Переопределяет безопасность инбаунда для подключения. |
| Использовать адрес как SNI | Переключатель | Подставляет адрес хоста в SNI. |
| ALPN | Мультиселект | Протоколы TLS ALPN. Очистка выбора задаёт пустой список. |
| Fingerprint | Селект | Профиль TLS ClientHello: готовый, случайный или стандартный TLS Go (`unsafe`). |
| Не проверять сертификат | Переключатель | Отключает проверку сертификата сервера. |
| Host | Текст | Host транспорта. Через запятую — случайный выбор; `*` — случайная строка. |
| Путь | Текст | Путь транспорта или имя сервиса gRPC. Доступны переменные. |
| Использовать SNI как Host | Переключатель | Подставляет SNI в Host транспорта. |
| Случайный User-Agent | Переключатель | Выбирает случайный HTTP User-Agent подключения. |
| Дополнительные параметры XHTTP | JSON-объект | Заменяет extra инбаунда целиком. Пропущенные ключи используют значения по умолчанию клиента. GET требует packet-up. |
| MUX | JSON-объект | Несколько потоков в одном соединении. `enabled` включает MUX; `xray` и `smux` задают его параметры. |
| Фрагментация | `length,interval,packets` | `length` — байты, `interval` — мс; число или диапазон A-B. `packets` — tlshello или номера пакетов. |
| Шум | `type:value[,delay]` | Типы rand, str, hex, base64; delay — мс. Несколько пакетов разделяются `&`. Для Xray JSON. |
| SockOpt | JSON-объект | Параметры сокета Xray: TCP, DNS и сетевой интерфейс. Интервалы KeepAlive — в секундах. |
| Final mask | JSON-объект | Маски TCP/UDP и параметры QUIC для Xray JSON. Маски применяются от внутренней к внешней. |
| Параметры клиента | JSON-объект | `clash` — параметры IP и X25519; `server_description` — описание сервера. |
| Mapper | JSON-объект | Операции set, copy, unset для xrayJson, clash, singbox и base64. Выполняются по порядку. |
| Шаблоны | Комбобокс | По одному шаблону на формат. Удаление чипа исключает формат. |
| Скрыть из списка | Переключатель | Исключает отдельное подключение из подписок, сохраняя доступ для составных шаблонов. |

## Переопределения

| Раздел | Поля |
| --- | --- |
| `security` | `mode`, `sni`, `sni_from_address`, `alpn`, `fingerprint`, `allow_insecure` |
| `transport` | `host`, `path`, `use_sni_as_host`, `random_user_agent`, `xhttp.extra` |
| `mux` | `enabled`, `xray`, `smux`; у smux собственное `enabled` |
| `stream` | Объекты `sockopt`, `final_mask` для Xray |
| `clients` | `clash.ip_version`, `clash.x25519`, `server_description` для Xray/Clash Meta |
| `fragment`, `noise` | Прежние строковые форматы фрагментации и шума |
| `mapper` | Операции `set`, `copy`, `unset` для `xrayJson`, `clash`, `singbox`, `base64` |

Полная актуальная JSON Schema доступна в `GET /api/hosts/capabilities`.
Неизвестные ключи отклоняются. Для [параметров сокета](socket-options.md) описаны
все поля Xray SocketConfig, Happy Eyeballs и варианты `customSockopt` с проверкой
типов, диапазонов и конфликтующих настроек KeepAlive. Та же схема применяется к `echSockopt`.
Для Final mask есть [подробная схема и справочник](finalmask.md): отдельные варианты
TCP/UDP-масок, вложенные параметры QUIC/TLS, кодировки и выражения заголовков.
Поле SNI и режим «SNI из адреса» взаимоисключающие. Пустое поле SNI задаёт
явную пустую строку; отсутствие поля сохраняет наследование. Ранее сохранённый
флаг пустого SNI преобразуется в `sni: ""` при чтении и последующем сохранении хоста.

Отсутствие поля при создании означает наследование/default. PATCH сохраняет
пропущенные поля. Внутри объектов PATCH `null` удаляет переопределение, массивы
заменяются целиком. `false`, `0`, путь `""` и ALPN `[]` являются явными значениями.
`overrides: null` очищает все переопределения; `port: null` возвращает порт инбаунда.
Списки групп и привязки шаблонов заменяются целиком.

### XHTTP

Полный [справочник XHTTP extra](xhttp.md) содержит все поля, ограничения,
диапазоны XMUX, параметры сессии, отдельного download-соединения и примеры методов.
Схема Monaco и API общая; проверяются также вложенные TLS/REALITY, параметры сокета
и Final mask. Числа, числовые строки и диапазоны (`"2-4"`, `"4-2"`) сохраняются
в исходном виде. Устаревший `scMaxConcurrentPosts` остаётся доступен для старых настроек.

Все дополнительные параметры имеют один источник:

```json
{
  "transport": {
    "xhttp": {
      "extra": {
        "scMaxBufferedPosts": 0,
        "xPaddingObfsMode": false,
        "uplinkHTTPMethod": "PUT"
      }
    }
  }
}
```

`extra` атомарен и при PATCH: объект целиком заменяет extra инбаунда, `{}` явно
очищает его, `null` удаляет override и возвращает наследование. Пропущенные ключи
в явном объекте используют defaults клиента. `null` внутри extra запрещён.
HTTP-метод обрезается по краям и переводится в верхний регистр. `GET` допустим
только для packet-up. Совместимость проверяется и при изменении инбаунда.

Xray получает `xhttpSettings.extra`/`splithttpSettings.extra`; URI — JSON в extra;
VMess — объект extra внутри Base64 payload. Clash Meta преобразует поддержанные ключи
в `xhttp-opts`. sing-box исключает неподдерживаемый XHTTP.

### Mapper

Объект содержит только ключи `xrayJson`, `clash`, `singbox`, `base64`.
Каждый ключ принимает упорядоченный массив операций, `[]` или `null`.
Пропущенный ключ, пустой массив и `null` не добавляют преобразований для формата.
Outline не использует mapper. В Monaco доступны примеры для каждого семейства,
операций и значений источника; та же схема используется для проверки запросов API.

| Операция | Обязательные поля | Действие |
| --- | --- | --- |
| `set` | `op`, `to`, `value` | Установить значение; объект или массив заменяется целиком |
| `copy` | `op`, `to`, `from` | Скопировать значение из инбаунда или разрешённых данных хоста |
| `unset` | `op`, `to` | Удалить ключ или элемент массива; остальные элементы сдвигаются |

У `set` нельзя указывать `from`, у `copy` — `value`, у `unset` — оба этих поля.
Неизвестные поля и операции отклоняются. `value` принимает любой JSON: строку, число,
boolean, `null`, массив или объект. `false`, `0`, `""`, `[]`, `{}` и `null` — явные значения.
В частности, `set` с `value: null` отличается от удаления через `unset`.

`to` задаёт путь внутри одного узла. Для URI это буквальный query-ключ;
для VMess изменяется payload. `copy.from` читает raw inbound или `$host.*`
(`address`, `port`, `finalRemark`, `protocol`, `protocolOptions`, `transport`, `security`, `metadata`).
Поддерживаются пути объектов и массивов; индексы ограничены 1024 элементами.
Отсутствующий источник copy пропускается. Mapper не изменяет полный документ.
Служебный Xray tag менять нельзя. После преобразования проверяются идентификаторы
и ссылки, включая группы и Xray dialer/routing.

| Семейство | Объект назначения | Примеры `to` |
| --- | --- | --- |
| `xrayJson` | Один Xray outbound | `streamSettings.sockopt.tcpFastOpen`, `settings.vnext[0].address` |
| `clash` | Один Clash proxy | `udp`, `ws-opts.headers.Host`, `alpn[0]` |
| `singbox` | Один sing-box outbound | `tls.server_name`, `transport.path`, `tls.alpn[0]` |
| `base64` | Query-параметры URI или верхний уровень VMess payload до кодирования | `sni`, `allowInsecure`; VMess также `add`, `port`, `ps` |

Для URI имя `a.b[0]` остаётся одним query-ключом; для JSON/YAML тот же путь
обращается к вложенному элементу. Mapper query-параметров не меняет схему URL,
адрес, порт, учётные данные или фрагмент ссылки. В VMess изменяются поля JSON payload.
Пути назначения не ограничены фиксированным списком нативных полей клиента.
Схема проверяет форму операций; применимость конкретного поля зависит от формата,
протокола и версии клиента. Индексы массивов и ссылки в итоговой конфигурации
дополнительно проверяются во время генерации.

Источники `from` всегда читаются из исходных данных, независимо от предыдущих операций:

| Источник | Значение |
| --- | --- |
| `port`, `settings.*`, `streamSettings.*` | Соответствующее поле исходного инбаунда |
| `$host.address`, `$host.port` | Адрес и порт после разрешения настроек хоста |
| `$host.finalRemark`, `$host.metadata.remark` | Итоговое примечание |
| `$host.protocol`, `$host.transport`, `$host.security` | Разрешённые протокол, транспорт и режим безопасности |
| `$host.protocolOptions` | Объект учётных данных пользователя для протокола |
| `$host.protocolOptions.id` | UUID для VLESS/VMess |
| `$host.protocolOptions.password` | Пароль для Trojan/Shadowsocks |
| `$host.protocolOptions.auth` | Учётные данные Hysteria |
| `$host.protocolOptions.method`, `$host.protocolOptions.flow` | Метод Shadowsocks или flow VLESS/Trojan |
| `$host.metadata` | Объект метаданных с `remark` |

У `from` также разрешены вложенные пути и индексы. Отсутствующий источник пропускается;
существующее значение `null` копируется. `set` и `copy` создают отсутствующие контейнеры,
`unset` их не создаёт. Пути назначения с `__proto__`, `__class__` или `constructor` запрещены.

```json
{
  "xrayJson": [
    { "op": "set", "to": "streamSettings.sockopt.tcpFastOpen", "value": true }
  ],
  "clash": [
    { "op": "set", "to": "udp", "value": false },
    { "op": "copy", "from": "$host.address", "to": "sni" },
    { "op": "unset", "to": "skip-cert-verify" }
  ],
  "singbox": [
    { "op": "copy", "from": "$host.address", "to": "tls.server_name" }
  ],
  "base64": [
    { "op": "set", "to": "sni", "value": "example.com" }
  ]
}
```

Ранее сохранённые операции сохраняют поведение: лишние неиспользуемые `from`/`value`
убираются при чтении и последующем сохранении, а пропущенный старой сериализацией
`value` у `set` читается как `null`. Само чтение не изменяет строки базы данных.

## Выдача и композиция

Скрытый хост не выдаётся отдельным подключением ни в одном формате, включая
URI/Base64 и Outline, даже если ни один шаблон его не использовал. Он может быть
выбран директивой шаблона как источник составной конфигурации.
Если все хосты скрыты, обычная подписка пуста. Составной default или явно выбранный
шаблон Clash/sing-box может использовать скрытые источники при `selectFrom: "ALL"`
или `"HIDDEN"`; Xray требует видимого получателя.
Outline сохраняет прежний контракт одного SS-объекта из видимых подключений.
Выключенный хост, запрещённый инбаунд, отсутствие привязки формата и неподдерживаемый
транспорт исключают источник до применения директив. Шаблоны источников не вкладываются.
Фильтр групп ограничивает получателей и стандартный видимый список; явный селектор
может выбрать другие разрешённые пользователю источники.

## API

Все операции требуют sudo. Префикс `/api/hosts`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `` | `items`, `total`; search/groups/inbound_id/enabled/offset/limit |
| POST | `` | Создание, ответ 201 |
| GET, PATCH, DELETE | `/{id}` | Чтение, PATCH, удаление (204) |
| POST | `/{id}/clone` | `{remark}`; выключенная копия параметров, групп и привязок (201) |
| POST | `/reorder` | `{host_ids: [...]}`; все ID ровно один раз |
| GET | `/capabilities` | Версия 4, JSON Schema переопределений, форматы |
| POST | `/preview` | `{host, host_id?, user_id, target}`; получатели и причины исключений без записи |

`groups` — ID через запятую; `limit` до 1000, по умолчанию 100.
Ошибки: 401/403 — доступ; 404 — ID; 409 — конфликт данных; 422 — неверные данные.
Поля прежних связей и балансировки отклоняются. Старый API не сохраняется.

## Распределение ответственности

`SubscriptionSnapshotLoader` читает БД и создаёт отделённый снимок.
`ProfilePlanner` получает снимок, формат, credentials пользователя, разрешённые инбаунды
и фильтр получателей. Внутри `ConnectionCatalog` проверяет доступ и использует
`ConnectionResolver`, чтобы один раз разрешить собственные параметры каждого источника.
`TemplateSelector` выбирает явный `template_id` при его наличии. Иначе для URI и
Xray JSON используется привязка получателя, а для sing-box, Clash и Outline — текущий
default формата из снимка каталога. Общий шаблон не ищется по хостам или содержимому.
Привязки общих форматов сохраняются, но определяют только включение формата.
В общем комбобоксе хоста эти форматы представлены чипсами текущих defaults;
удаление чипа выключает формат, повторный выбор включает его. Для URI/Xray JSON
доступны все шаблоны соответствующего формата.
Источники могут быть видимыми и скрытыми; выбор не обходит права пользователя.

`GeneratorRegistry` передаёт `RenderInput` сборщику формата. Xray-сборщик создаёт
отдельный документ для каждого получателя; Clash и sing-box собирают общий документ.
`template_directives` проверяет служебные параметры и выбирает источники;
сборщики `composition` обрабатывают группы и провайдеры. Неиспользуемые скрытые
подключения не передаются в форматные builders и mapper.
`OutputValidator` проверяет идентификаторы, ссылки, циклы и обязательные группы после сборки.
Генераторы не обращаются к БД и не изменяют исходный снимок.

## Миграция композиции

Ревизия `e5c14a9d72b0` выполняет один прямой переход от `f6a82c1d5e90`
(схема ветки `master`) к текущей модели. Миграции `master` сохранены без изменений.
Промежуточные ревизии этой ветки объединены: таблица `host_links`, поля
`show_when_composed`/`balancer_settings` и переименования `clash` больше не создаются.

Миграция проверяет преобразование перед DDL и сохраняет исходные хосты,
балансировщики с участниками, шаблоны, привязки к шаблонам и группам, а также инбаунды
в `host_composition_archive`. Исходные ID, порядок, привязки и состояние хостов
сохраняются. Старые параметры сразу становятся `overrides`, включая `0` и `false`
в `transport.xhttp.extra`. Исходные хосты остаются видимыми (`is_hidden = false`).

Для каждого старого балансировщика с доступными Xray-источниками создаются конечный
хост-получатель и собственный шаблон только `v2ray-json`. Шаблон выбирает исходных
участников по ID; временных хостов-владельцев нет. Получатель наследует адрес и
инбаунд первого подходящего источника, имя, состояние и даты балансировщика,
а также объединение групп его участников. Для Clash/sing-box настройки нативных групп
связываются с общим шаблоном и применяются после его рендеринга. Учитываются совместимость протоколов и выключенные
форматы источников. Выключенный балансировщик сохраняется в служебных настройках как неактивная
группа; его Xray-получатель выключен.

Стратегия Xray переносится как `leastPing`, `leastLoad`, `random` или `roundRobin`.
Clash использует `load-balance`/`round-robin` для `round_robin`, иначе `url-test`;
sing-box использует `urltest`, как и прежний генератор. URL и интервал проверки
переносятся из балансировщика. Текст существующих шаблонов сохраняется без изменений,
включая пользовательский Jinja. Генерируемые Jinja-обёртки и фильтры в него не добавляются.
Служебный JSON `subscription_templates.migration_settings` содержит версию преобразования,
нативные секции Xray либо группы Clash/sing-box с ID участников и признаком активности.
Для Clash также сохраняется режим явных списков групп. После рендеринга backend
дополняет документ этими секциями, корректирует маршрутизацию Xray и применяет
директивы `marzban` с обычной проверкой доступности источников. Активные имена групп
Clash доступны исходному Jinja через `proxy_remarks`, как до переноса.
Данные переноса сохраняются при редактировании и клонировании шаблона;
при разрешённой смене формата у неиспользуемого шаблона они сбрасываются.
Они не входят в текст редактора или клиентскую подписку. Новые шаблоны используют
директивы `marzban` непосредственно в конфигурации. ID, имена, отметки default
и даты существующих шаблонов сохраняются; формат остаётся `clash` на всём переходе.

Пустые балансировщики, неизвестные стратегии, некорректные параметры хостов или
инбаундов, повреждённые привязки к шаблонам и группам, несовместимые общие шаблоны
и конфликтующие observatory останавливают миграцию до изменения схемы.
Новые даты хостов записываются с точностью до секунды, одинаково для SQLite и
MySQL/MariaDB, чтобы сверка с архивом при откате учитывала точность хранения.
Read-only проверка:

```sh
python scripts/host_preflight.py --database-url sqlite:///backup.db
```

Downgrade восстанавливает исходные данные и схему `master`, только если хосты,
шаблоны, их привязки и инбаунды с момента обновления не изменились. При новых
правках откат прекращается, чтобы их не затереть. Проверки выполняются на временных
SQLite-базах с внешними ключами и без них; DDL таблиц также компилируется для
MySQL/MariaDB, но это не заменяет проверку на работающем сервере этих СУБД.

Единая миграция поддерживает только переход со схемы `master`. Если в
проверочной БД уже применены удалённые промежуточные ревизии ветки, используйте
сохранённую копию `master` или пересоздайте проверочную БД с переносом нужных данных.
Простая смена `alembic_version` не преобразует данные и архив отката.
Рабочая БД автоматически не меняется при правках исходников. Обновляйте backend
и dashboard вместе и выполняйте `alembic upgrade head` после резервного копирования.
