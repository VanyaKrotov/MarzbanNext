# Параметры сокета в настройках хоста

Поле хранится в `overrides.stream.sockopt` и передаётся в
`outbounds[].streamSettings.sockopt` клиентской конфигурации Xray.
Clash, sing-box, URI/Base64 и Outline этот объект не получают.
Настройки применяет ядро на устройстве клиента, а не master-панель или сервер инбаунда.

«Настроить» открывает Monaco с описаниями, примерами, автодополнением и проверкой
значений. API использует ту же модель. Неизвестные поля отклоняются, включая
неизвестные поля вложенных `happyEyeballs` и `customSockopt`.
Эта же схема используется для `tlsConfig.echSockopt` в Final mask.

Источник контракта — [SocketConfig Xray](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/infra/conf/transport_sockopt.go),
ревизия `1b1647cd9ddf0abc34b981d4611fc03bcac1ca74`.
Особенности применения проверены по `transport/internet/system_dialer.go`,
`happy_eyeballs.go`, `sockopt_linux.go`, `sockopt_windows.go`, `sockopt_darwin.go`
и `splithttp/dialer.go` этой ревизии.

## Формат и сохранение

В редакторе вводится сам объект сокета:

```json
{
  "tcpFastOpen": true,
  "tcpKeepAliveIdle": 45,
  "tcpKeepAliveInterval": 45,
  "domainStrategy": "UseIP",
  "happyEyeballs": {
    "tryDelayMs": 250,
    "prioritizeIPv6": false,
    "interleave": 1,
    "maxConcurrentTry": 4
  }
}
```

Все верхнеуровневые поля необязательны; `{}` допустим. Значения по умолчанию
не добавляются при сохранении. `false`, `0`, `-1`, пустая строка и пустой массив
сохраняются явно. Пропущенные поля используют поведение ядра.
Удаление поля в форме возвращает наследование; `null` в PATCH удаляет конкретное
переопределение. Массив `customSockopt` при PATCH заменяется целиком.

Имена `tcpcongestion` и `tcpCongestion`, а также `V6Only` и `v6only` поддерживаются
без переименования сохранённых ключей. При сериализации модель сохраняет порядок
ключей: Xray использует последнее значение из двух форм. Для однозначной настройки
задавайте одну форму. Значения DNS-стратегий и `tproxy` нечувствительны к регистру,
но при сохранении исходное написание не меняется.

## TCP

Обычные целые поля сокета имеют диапазон signed int32: −2147483648…2147483647.
Строка вместо числа или boolean вместо целого не принимаются.

| Поле | Значение |
| --- | --- |
| `tcpFastOpen` | Boolean или целое: `true`/положительное число включает TFO, `false`/отрицательное отключает, `0`/отсутствие оставляет выбор ОС. На слушателе положительное число задаёт лимит ожидающих запросов, `true` соответствует 256 |
| `tcpKeepAliveIdle` | Пауза до первой KeepAlive-пробы, секунды. Для клиентского TCP `0` сохраняет default ядра — 45 секунд. Отрицательное значение отключает KeepAlive |
| `tcpKeepAliveInterval` | Интервал между KeepAlive-пробами, секунды. Для клиентского TCP default — 45 секунд; отрицательное значение отключает KeepAlive |
| `tcpUserTimeout` | Linux: время ожидания подтверждения данных в миллисекундах. Неположительное значение не меняет системную настройку |
| `tcpMaxSeg` | Linux: максимальный TCP-сегмент, байты, например 1440. Неположительное значение не меняет системную настройку |
| `tcpWindowClamp` | Linux: ограничение объявляемого окна приёма, байты. Неположительное значение не меняет системную настройку |
| `tcpcongestion` | Linux: название алгоритма, например `bbr`, `cubic`, `reno`. Допускаются и другие имена, доступные ядру клиента. Пустая строка сохраняет выбор ОС |
| `tcpCongestion` | Другая допустимая форма имени `tcpcongestion` |
| `tcpMptcp` | Boolean: использовать Multipath TCP при поддержке клиентской ОС и ядра |

Для KeepAlive нельзя сочетать положительное значение одного поля с отрицательным
значением другого: Xray отклоняет такое соединение. Эта комбинация проверяется
в Monaco и API. Для отключения достаточно `tcpKeepAliveIdle: -1`, если интервал
не задан или равен нулю.

## DNS и установление соединения

| Поле | Значение |
| --- | --- |
| `domainStrategy` | `AsIs`/`""` — системный resolver; `Use*` — DNS Xray с системным fallback; `Force*` — ошибка при невозможности получить подходящий IP |
| `addressPortStrategy` | `none`/`""`, `SrvPortOnly`, `SrvAddressOnly`, `SrvPortAndAddress`, `TxtPortOnly`, `TxtAddressOnly`, `TxtPortAndAddress`. Переписывает адрес и/или порт через системные SRV/TXT-записи до `domainStrategy` |
| `happyEyeballs` | Параметры параллельных TCP-попыток к разрешённым адресам; структура ниже |
| `dialerProxy` | Tag существующего outbound для цепочки подключений. `""` выключает цепочку. Генератор проверяет наличие tag; автоматически созданный fragment/noise dialer имеет приоритет |

Полный набор `domainStrategy`: `AsIs`, `UseIP`, `UseIPv4`, `UseIPv6`, `UseIPv4v6`,
`UseIPv6v4`, `ForceIP`, `ForceIPv4`, `ForceIPv6`, `ForceIPv4v6`, `ForceIPv6v4`, `""`.
У прокси-outbound эта стратегия разрешает адрес прокси-сервера.
`IPv4v6`/`IPv6v4` задают порядок DNS-разрешения семейств, а не переключение после
неудачного TCP-соединения к уже полученному IP.

| Поле `happyEyeballs` | Формат |
| --- | --- |
| `tryDelayMs` | Неотрицательное uint64, задержка в мс. `0` отключает механизм; пример — 250 |
| `prioritizeIPv6` | Boolean; default `false` — IPv4 первым |
| `interleave` | Неотрицательное uint32, число адресов одного семейства подряд; default 1. `0` оставляет первое семейство одной группой |
| `maxConcurrentTry` | Неотрицательное uint32, одновременные попытки; default 4. `0` отключает механизм |

Happy Eyeballs Xray действует для TCP при разрешении через DNS Xray и без
непустого `dialerProxy`. С `AsIs` поведение определяет системный dialer.
Панель позволяет сохранить такие сочетания, но описывает ограничение в подсказках.

## Платформа и транспорт

| Поле | Значение |
| --- | --- |
| `mark` | Linux SO_MARK в signed int32-представлении. `0` не задаёт метку. Требуются соответствующие права процесса клиента |
| `interface` | Имя интерфейса клиента для исходящего соединения, например `wg0`; `""` не привязывает интерфейс |
| `tproxy` | `off`/`""`, `redirect`, `tproxy`; Linux transparent proxy с соответствующими правилами ОС и правами |
| `V6Only`, `v6only` | Boolean: Linux-слушатель на `::` принимает только IPv6. В клиентском outbound хоста эффекта нет |
| `acceptProxyProtocol` | Boolean: приём PROXY protocol на инбаунде. В клиентском outbound хоста эффекта нет |
| `trustedXForwardedFor` | Массив имён HTTP-заголовков. На HTTP-инбаундах наличие любого из них разрешает доверять X-Forwarded-For. В клиентском outbound хоста эффекта нет |
| `penetrate` | Boolean: при отдельном XHTTP `downloadSettings` заменить его socket options параметрами upload-соединения |

## Собственные параметры ОС

`customSockopt` — массив вызовов setsockopt. Для каждого элемента обязательны
`type`, `opt`, `value`. `level`, `opt` и числовой `value` вводятся **строками**.

```json
{
  "customSockopt": [
    {
      "system": "linux",
      "network": "tcp",
      "type": "str",
      "level": "6",
      "opt": "13",
      "value": "bbr"
    }
  ]
}
```

Это пример установки Linux TCP_CONGESTION через строковое значение.

| Поле элемента | Формат |
| --- | --- |
| `system` | `""`, `linux`, `windows`, `darwin`, `android`; пропуск/пустая строка не ограничивает ОС. Android означает отдельную Android-сборку ядра |
| `network` | `""`, `tcp`, `tcp4`, `tcp6`, `udp`, `udp4`, `udp6`; `tcp`/`udp` охватывают оба семейства |
| `type` | `int` или `str`; редактор подбирает соответствующую схему `value` |
| `level` | Десятичная целочисленная строка; пропуск/`""` использует 6 (TCP) |
| `opt` | Непустая десятичная целочисленная строка с номером параметра; hex-запись не принимается |
| `value` для `int` | Десятичная строка со знаком или без него, например `"1"`, `"0"`, `"-1"`; API проверяет диапазон signed int64 |
| `value` для `str` | Произвольная строка, включая `""` |

Xray Windows не поддерживает строковый setsockopt: явная комбинация
`system: "windows"`, `type: "str"` отклоняется схемой. При пустом `system`
фактическую поддержку проверяет устройство клиента.
Наличие интерфейса, алгоритма congestion control, права процесса и допустимость
номеров/значений конкретного socket option проверяет ОС клиента.

Модель схемы: `app/models/socket_options.py`. Полный контракт публикуется
в `GET /api/hosts/capabilities`, `overrides_schema`.
